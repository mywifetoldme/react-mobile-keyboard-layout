**Status**: 🏆 **WINNER (채택)** | 🎮 **[이 실험 샌드박스 실행](https://react-mobile-keyboard-layout.pages.dev/#labs?exp=exp03_e)**

#### 🎯 실험 가설
> 사파리 브라우저의 0.35초 지연 알림을 기다리지 않고, 사용자가 포커스를 해제하는 즉각(0ms) 화면 전체 복원과 스크롤 원복, 플로팅 바닥 안착을 단일 프레임에 원자적(Atomic)으로 일괄 실행하면, 화면 중간 뜸과 시차 없이 바닥에 즉시 매끄럽게 안착될 것이다.

react-mobile-keyboard-layout 라이브러리의 최종 공식 프로덕션 엔진으로 채택 및 배포.

### EXP-03-F: 뷰포트 경계 회피를 통한 사파리 개입 무력화

**Status**: 🏆 **WINNER (채택)** | 🎮 **[이 실험 샌드박스 실행](https://react-mobile-keyboard-layout.pages.dev/#labs?exp=exp03_f)**

#### 🎯 실험 가설
> 본문 최하단 인풋 포커스 시 스크롤 컨테이너 경계 근처의 인풋을 안쪽으로 살짝 정렬(안전 여백 16px, 데드존 2px)하여 사파리가 "이미 잘 보인다"고 판단하게 만들면, 키보드가 솟아오르다 다시 내려가는 충돌을 원천 방지할 수 있다.

#### 📊 6대 평가 기준 매트릭스

| 평가 항목 | 결과 | 상세 결과 및 관찰 내용 |
| :--- | :---: | :--- |
| **1-1. 키보드 활성화 시 상단 헤더 고정** | `✅ PASS` | 상단 헤더 0.0px 완전 고정 달성 |
| **1-2. 키보드 활성화 시 단일 스크롤 유지** | `✅ PASS` | 단일 스크롤로 매끄럽게 통합 유지 |
| **1-3. 키보드 활성화 시 Safe Area Inset 제거** | `✅ PASS` | Safe Area Inset 제거 및 8px 초밀착 성공 |
| **1-4. 키보드 활성화 시 바디 하단 스크롤 앵커링** | `✅ PASS` | 안전 경계 정렬 중에도 스크롤 앵커링 완벽 보존 |
| **2-1. 본문 폼 입력 시 포커스 핸드오버** | `✅ PASS` | 최하단 본문 인풋 포커스 시 키보드 튕김/내려감 현상 완전 차단 |
| **3-1. 본문 포커스 해제 시 깜빡임 없는 복원** | `✅ PASS` | 중간 뜸 현상 완전 제거 및 닫힘 시 바닥 즉시 안착 완료 |

#### 💡 핵심 발견점 (Key Finding)
사파리의 개입을 "막는 것"과 "회피하는 것"은 전혀 다른 수단입니다. 앞선 해법들이 사파리의 쓰기를 차단하는 방향(scrollTo(0,0) 락, touch-action: none, preventScroll)이었던 것과 달리, 이번 해법은 사파리가 개입할 조건 자체를 없애는 방향입니다. (중요: 여기 쓰인 16px 경계 여백과 2px 데드존은 브라우저의 물리적 임계값이 아니라 육안으로 어색하지 않게 맞춘 시각적 튜닝 값입니다.)

#### ➡️ 다음 설계 결정 (Next Decision)
core layoutRules의 alignElement 로직으로 공식 채택. 해당 16px/2px 수치는 육안으로 조율된 값이므로 추후 훅 옵션(alignPadding 등)으로 개방하여 사용자가 커스텀할 수 있도록 지원할 예정.
